Tribunal

  • Prosecutor and Defender argue opposite sides, a deterministic verifier checks every quote
  • 96% quote grounding, 83% polarity accuracy on 32 hand-labelled claims
  • Ships as CLI, streaming web UI, and MCP server
Adversarial multi-agent fact-checker. A Prosecutor and Defender argue opposite sides of a claim over retrieved evidence; every quote is checked against the source text by a deterministic verifier before a Judge rules, so no LLM grades its own output. The adversarial structure exists because a single model asked "is this true?" tends to agree with how the question is framed. On a 32-claim balanced set, deliberately small and hand-labelled: 96% quote grounding, 83% polarity accuracy, 66% strict accuracy. The more useful number is the error breakdown, not the top line: the dominant failure is calling a "misleading" claim flatly "false", a specific gap in the Judge prompt, not a vague limitation.

PythonRAG Evals
  • From-scratch HRM reproduction (arXiv:2506.21734): a slow planner, a fast executor
  • 100% maze-path accuracy, 66.7% fewer compute steps via ACT halting
  • A documented negative result on 9×9 Sudoku, not hidden
From-scratch PyTorch reproduction of Sapient's Hierarchical Reasoning Model (arXiv:2506.21734): a slow planner and a fast executor solving reasoning tasks in a single forward pass. 100% path accuracy on 5×5 maze pathfinding by epoch 20, a 66.7% compute reduction from ACT halting, 49 passing tests across 8 controlled experiments. On a simple arithmetic task a flat RNN beats it outright, 7.5K params to 17K, lower loss: hierarchy only pays off once the task actually needs it. 9×9 Sudoku is the counterexample where it doesn't: 15.9% cell accuracy against an 11.1% random baseline, a real architectural gap, root-caused and documented rather than hidden.
PythonPyTorch
  • Learns a UI task once, replays it deterministically with no model after that
  • Hands control to a human mid-task when it can't proceed safely
  • Tested against a deliberately legacy mock bank with injected faults
An LLM works out how to complete a task inside a UI with no API; the successful run compiles into a typed, versioned capability that replays afterward deterministically, with no model in the loop. Replay returns success, a named business outcome (e.g. MEMBER_NOT_FOUND, not a crash), or a debuggable failure. When it can't proceed safely, it hands the live session to a human and takes it back. Tested against a deliberately legacy mock banking app with injectable faults: the committed evidence covers 7 reproducible scenarios, including two mid-flow faults, an unknown popup and a session expiry, that get learned once and replayed afterward with no model involved.
